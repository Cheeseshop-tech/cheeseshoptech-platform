# Onboarding Engine — doc set

**Created 2026-09-07** to split Rick's platform-vision brain-dump (previously one long
artifact/memory thread) into an actual engineering scope: what's really being built right now
(the Onboarding Engine itself) versus every future app function it was getting bundled together
with (social automation, self-redesigning storefront, ops backbone, distributor portals,
e-commerce completion). One document per section, all in this folder, so each piece can move at
its own pace without the others reading as equally "next."

**Read in this order:**

1. **`01-CORE-BUILD.md`** — the actual Onboarding Engine. This is Phase 0, active now: ingest a
   brand's content, extract brand voice + design system, derive a design algorithm, generate
   output templates from it. Proven against Monti Trentini, not a second brand yet.
2. **`07-SALES-OUTREACH-ENRICHMENT-STATUS.md`** — not a future doc, a status note. This piece is
   already the most mature part of the whole vision (HubSpot CRM live, Booth→HubSpot live,
   Enrichment Campaigns already a real campaign type) and is what actually gets stress-tested at
   the ACE Endico Fall Show, 2026-09-15.
3. **Everything else in this folder is FUTURE — not yet built, not yet scheduled**, in the rough
   order they come up in Rick's own sequencing (see the Unified Direction doc, one level up):
   - `02-CAMPAIGN-AND-STOREFRONT.md`
   - `03-OPERATIONS-BACKBONE.md`
   - `04-DISTRIBUTOR-PORTALS.md`
   - `05-SOCIAL-AUTOMATION.md`
   - `06-ECOMMERCE-EXPANSION.md`

**Where this fits in the bigger picture:** `../CST_UNIFIED_DIRECTION_2026-09-07.md` is the
single doc that reconciles this scope against the older, sometimes-conflicting scope docs
(`PROJECT_ROADMAP.md`, `PROJECT_STATUS.md`, the 2026-09-03 priority roadmap, the hardening plan).
Read that first if you're trying to figure out what to build THIS WEEK — these docs describe
WHAT each piece is, not when it's scheduled. `../CST_DEVELOPMENT_STATUS_2026-09-07.md` is the
fresh, whole-platform status inventory that grounds all of it against the real codebase.

**Ground rule for every doc in this folder:** grade status honestly — real/built, partial,
scoped-not-built, or idea-not-scoped. Don't let a "future" doc read as more built than it is
just because it's now written down carefully.
